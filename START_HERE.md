# Оля, начните отсюда

Подготовлено 22 октября 2026 года к передаче сайта 23 октября.

Сайт работает по адресу [shirokostup.site](https://shirokostup.site/). Это статический сайт: тексты и события редактируются в файлах, а публикация проходит через GitHub. Админки и серверной базы данных здесь нет. Архив позволяет продолжить работу на другом компьютере и восстановить сайт.

## Что находится в архиве

| Файл или папка | Для чего |
| --- | --- |
| `project/` | Редактируемый проект: тексты, события, исходные стили и скрипты, фотографии, CV, правила, сборка и тесты |
| `site/` | Готовые публичные файлы текущей версии; можно смотреть или размещать без сборки |
| `site-history.bundle` | История ветки `main` для восстановления Git-репозитория |
| `MANIFEST.json` | Точная версия исходников, проверенный выпуск и состав передачи |
| `CHECKSUMS.sha256` | Контрольные суммы всех файлов комплекта |
| `licenses/` | Копия условий Dinamo для включённого веб-шрифта и сведения об источнике |

Исходные фотографии здесь — те файлы, которые используются в сайте. Полноразмерные авторские оригиналы и редактируемый исходник CV, если они хранятся отдельно, архивом не подменяются.

## Сначала посмотреть

Распакуйте ZIP. Откройте терминал в папке `site/` и выполните:

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

Откройте [127.0.0.1:4173](http://127.0.0.1:4173/). Остановка сервера — `Ctrl+C`. Для простого просмотра Node.js и установка зависимостей не нужны. Открытие HTML двойным щелчком не заменяет локальный сервер: модули и ссылки рассчитаны на HTTP.

## Продолжить работу

Рабочая папка — `project/`. Откройте именно её в редакторе или Codex. Прежде чем менять сайт, прочитайте [правила проекта](AGENTS.md); для агента они обязательны вместе с [общими правилами владельца](references/owner-project-rules.md). Они включены в архив и не зависят от доступа к прежнему чату или Notion.

Нужны **Node.js 24**, **pnpm 11.9.0** и **Python 3**. Из терминала в `project/`:

```bash
node --version
npm install --global pnpm@11.9.0
pnpm install --frozen-lockfile
pnpm run fonts:prepare
pnpm run build
pnpm run check
python3 -m http.server 4173 --bind 127.0.0.1
```

Установку `pnpm` пропустите, если нужная версия уже установлена. Команды не требуют `sudo`. Если компьютер ограничивает глобальную установку npm, настройте пользовательскую установку Node/pnpm; не обходите ограничения прав. В частном архиве уже есть точный веб-шрифт ABC Areal; дополнительные файлы из компьютера Антона для сборки не нужны. При первом `pnpm install` понадобится интернет. Папка `node_modules` устанавливается заново на каждом компьютере.

## Что и где менять

| Задача | Файл и порядок |
| --- | --- |
| Исправить описание проекта, биографию, запись хронологии или публикацию | `content/site.json`, затем `pnpm run build` |
| Добавить событие | `content/events.json`; образец и правила времени — в [HANDOFF.md](HANDOFF.md#добавить-предстоящее-событие) |
| Обновить CV | Заменить `assets/olga-shirokostup-cv.pdf`, проверить PDF и ссылку |
| Обновить фотографию | Сохранить исходный JPG в `assets/images/`, обновить подпись/alt и `assets/images/CREDITS.md`; сгенерировать варианты по [HANDOFF.md](HANDOFF.md#добавить-или-заменить-изображение) |
| Поменять контакты или структуру страницы | `index.html` вне блоков `GENERATED:*`; сохранить одинаковые реквизиты во всех местах |
| Исправить внешний вид | `styles/*.css`; `styles.css` создаётся сборкой |
| Изменить поведение | `src/script.js`; `script.js` создаётся сборкой |

В `index.html` блоки между комментариями `GENERATED:*` создаются из данных: ручная правка потеряется при следующей сборке. `404.html` содержит собственную разметку, но адреса собранных CSS/JS также обновляются автоматически. Не меняйте структуру JSON ради одного текста. Если сборка сообщает ошибку, сначала исправьте данные, не убирайте проверку.

После любой правки сайта выполните `pnpm run build` и `pnpm run check`, затем откройте изменённый раздел вместе с соседними блоками. Для интерфейса действуют [порог доступности](ACCESSIBILITY.md), [редакционные правила](EDITORIAL_STYLE.md) и подходящий сценарий из [DESIGN_EVALS.md](DESIGN_EVALS.md). Для полной браузерной проверки:

```bash
pnpm exec playwright install chromium webkit
pnpm run test:browser
```

На Linux движкам могут понадобиться системные зависимости: Playwright сообщит их список; в CI используется `playwright install --with-deps chromium webkit`. Повторные запуски для скрытия падений и ослабление проверок не допускаются.

Пример задания агенту для обычного обновления:

> Прочитай AGENTS.md и связанные правила. Обнови [конкретный текст или событие] по [источнику]. Сохрани принятую композицию и изображения. Сначала назови результат и критерии готовности, затем измени исходники, собери и проверь затронутый раздел на телефоне и большом экране в светлой и тёмной темах. Не публикуй, пока проверки и просмотр не подтвердят результат.

## Принятая основа

Сохраняем редакционную композицию, авторские материалы и изображения, разные роли разделов, шрифты ABC Areal и существующую серифную гарнитуру, светлую и ночную палитры, режим System, управление движением, две стопки фотографий и механизм событий. Приведение в порядок не означает новый дизайн всех разделов.

В футере общий знак Антона остаётся слева от имени с выносом за текстовую сетку на широком экране, на телефоне — отдельной строкой близко к имени. Подпись ведёт на `https://gorokhovatsky.tech/?point=shirokostup`. Возвращать удалённые `Back to top`, `About this website` и стрелки в утилитарные ссылки не нужно. [Подключение подписи](docs/author-signature.md) не требует локального копирования её рисунка.

У `Visit the exhibition` в Arctic Art Forum сохранена пометка `In Norwegian`: английской версии самой страницы музей не предлагает. В датах архива сохраняется различие между инициированием в 2022 году и последующими этапами; год 2023 в существующих записях не заменять автоматически.

## Опубликовать изменения

Для продолжения работы с историей удобнее клонировать [действующий репозиторий](https://github.com/anton-gorokhovatsky/shirokostup) в отдельную папку или восстановить его из bundle по [HANDOFF.md](HANDOFF.md#из-git-bundle). Затем скопировать веб-шрифт из `project/assets/fonts/` в ту же папку нового клона. Папка `project/` в ZIP не содержит `.git`.

После проверки конкретных изменений сохраните их коммитом. Push в `main` запускает `Quality gate`: проверки, браузеры и публикация GitHub Pages. PR проверяется, но не публикуется. Дождитесь успешных проверки и `deploy` в [Actions](https://github.com/anton-gorokhovatsky/shirokostup/actions), затем откройте публичный сайт и проверьте именно изменённый раздел. Push и зелёные тесты сами по себе ещё не подтверждают публичный результат.

Для ручного размещения готовых файлов `pnpm run package:site` создаёт новый `_site/`. Если он уже существует, сохраните нужную прежнюю копию вне проекта и удалите только этот результат сборки, затем повторите упаковку. На хостинг отправляются файлы из `_site/`, не вся рабочая папка. `site/` в переданном ZIP — снимок на момент передачи; после редактирования он сам не обновляется.

Архив не предоставляет права на GitHub, домен и Метрику. Отдельно нужно проверить доступ Ольги к репозиторию с правом записи, регистратору/DNS и автопродлению домена, счётчику `111895186`, а также передать редактируемый исходник CV и оригиналы материалов, если они нужны. Пароли и коды восстановления передаются отдельно.

При продолжении в прежнем репозитории настройки Pages и семь шрифтовых Secrets уже используются действующим workflow. При переносе в новый аккаунт/репозиторий нужно заново проверить доступы, Pages, домен и Secrets по [инструкции шрифта](assets/fonts/README.md). Не загружайте частный ZIP и WOFF2 в публичный GitHub.

Авторская подпись загружается с `gorokhovatsky.tech`; без сети остаётся обычная текстовая ссылка. Полная графическая подпись и согласованная посетителем аналитика требуют сети. Само содержимое сайта, фотографии, CV и шрифт находятся в комплекте.

Подробные операции, история решений и восстановление — [HANDOFF.md](HANDOFF.md).
